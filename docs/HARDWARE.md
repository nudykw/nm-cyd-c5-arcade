# Плата NM-CYD-C5 — залізо, розпіновка, особливості прошивки

> Дошка **NM-CYD-C5** (RockBase / NMTech): **ESP32-C5-WROOM-1** (RISC-V RV32IMAC, 240 MHz, без FPU),
> **16 MB** зовнішньої флеш-пам'яті, **8 MB** PSRAM, 2.8" TFT **320×240 ST7789**, резистивний тач
> **XPT2046**, слот **microSD**. Усе — на одній шині SPI2, пристрої розрізняються лініями CS.
>
> Піни взяті з вендорської документації (`Documention/2-sch/SCH_NM-CYD-C5-v1.0.pdf`,
> `User_Setup-NM-CYD-C5.h`) і **перевірені на живому залізі** в цьому проєкті: дисплей, тач, microSD,
> консоль UART0.

## Розпіновка (використовується в `crates/cyd-c5-common`)

| пристрій | лінії |
|---|---|
| **ST7789** (дисплей) | SCK **IO6**, MOSI **IO7**, MISO **IO2**, CS **IO23**, DC **IO24**, BL **IO25**, RST — пін RST плати |
| **XPT2046** (тач) | CS **IO1**, та сама шина SPI (6/2/7), IRQ не виведений, такт **2.5 MHz** |
| **microSD** | CS **IO10**, та сама шина SPI (6/2/7), ініціалізація на **400 kHz**, далі **16 MHz** |
| **UART0 → CH340** | TX **IO11**, RX **IO12**, **115200 8N1** — консоль, заливка, знімки екрана |
| WS2812 RGB LED | **IO27** |
| кнопки | BOOT **IO28**, RST — EN |

Дисплей працює в орієнтації `Deg270` (`MADCTL 0xA0`) — саме під неї відкалібрований тач у
`cyd_c5_common::touch`; зміна орієнтації вимагає нового калібрування.

### Обов'язкові правила ініціалізації шини

1. **Усі три CS (`IO23` дисплей, `IO1` тач, `IO10` SD) підняти в `HIGH` ДО старту SPI2** — інакше
   вставлена SD-картка «глушить» MISO і дисплей не ініціалізується (це вже враховано в `Board::init`).
2. Під час **читання з SD** тримати `MOSI = 0xFF`.
3. SPI дисплея — **40 MHz**; вище з'являються поодинокі чужі пікселі на однотонних ділянках.

## Два USB-порти плати

| порт | як виглядає | стан |
|---|---|---|
| **CH340** (UART-міст) | `/dev/ttyUSB0`, USB ID `1a86:7523` | **робочий**: прошивка, консоль, знімки екрана |
| **native USB-Serial-JTAG** (CDC) | `/dev/ttyACM0`, USB ID `303a:...` | на цій платі **не відповідає** (`Write timeout`, DTR/RTS не ресетять чип) |

Тому всі команди в цьому репозиторії використовують **`/dev/ttyUSB0`**. Якщо прошивка «зависла» і в
UART тиша, а на `ttyACM0` видно `alive` — це не поломка, а `esp-println` зібраний із `feature = "auto"`
(див. нижче).

## Чому `esp-println` тільки з `features = ["uart"]`

Крейт `esp-println` за замовчуванням (`auto`) вибирає USB-Serial-JTAG, щойно той живий, і пише туди.
На цій платі CDC-порт не вичитується, буфер швидко заповнюється, і **перший же `println!` вішає
прошивку**. У `Cargo.toml` воркспейсу зафіксовано:

```toml
esp-println = { version = "0.18.0", default-features = false, features = ["esp32c5", "uart", "critical-section"] }
```

Це інваріант: не змінювати на `auto`.

## Особливості прошивки саме ESP32-C5

- bootloader лежить за **`0x2000`** (не `0x1000`) — `espflash`/`idf.py` рахують це самі, руками нічого
  міняти не треба;
- флеш **16 MB** (дефолтні 2/4 MB — замало): у командах завжди `--flash-size 16mb`;
- `esptool` пише попередження `ESP32-C5 has no Chip ID. Reading MAC instead` — це норма;
- OTA-слоти (`ota_0`, `ota_1`) активуються через `otadata`; `espflash` цього не вміє, тому лаунчер
  робить це сам (`cyd_c5_common::boot`).

## Розмітка флеша (16 MB)

| зсув | розмір | розділ | що там |
|---|---|---|---|
| `0x009000` | 20 KB | `nvs` | калібрування тача, службові дані |
| `0x00E000` | 8 KB | `otadata` | який app-розділ завантажувати |
| `0x010000` | 1 MB | `factory` | **GameLauncher** |
| `0x110000` | 1 MB | `ota_0` | активна гра (завантажується з SD) |
| `0x210000` | 1 MB | `ota_1` | резервний слот |
| `0x310000` | 2 MB | `sdseed` | пакет `SDPK` для автоінсталяції ігор на microSD |
