# «Jewels» — match-3 на Rust для NM-CYD-C5 (ESP32-C5)

Гра «три в ряд» у стилі **Bejeweled**: поле 8×8, шість видів каменів, обмін сусідніх тапом,
каскади з множником. Pure-Rust, bare-metal: **esp-hal 1.2.2 + `mipidsi` + `embedded-graphics`**,
без RTOS, без LVGL, без алокатора.

```
nm-cyd-c5-jewels-rs/
├── Cargo.toml            features: framedump, demo
├── .cargo/config.toml    target riscv32imac-unknown-none-elf, runner = espflash --chip esp32c5
├── src/lib.rs            pub mod game
├── src/game.rs           правила match-3 + самотести (компілюється і на хості)
└── src/bin/main.rs       залізо, малювання каменів, анімації, ввід
```

## Збірка / заливка

```bash
cd ~/Projects/Esp32/nm-cyd-c5-jewels-rs
cargo build --release                    # ~4 с інкремент
espflash flash --chip esp32c5 --port /dev/ttyUSB0 \
  target/riscv32imac-unknown-none-elf/release/nm-cyd-c5-jewels-rs
```

Розмір app: **59 KB**, повний кадр **36 ms** (SPI 40 MHz + DMA), RAM: повний кадр 320×240 у
внутрішній RAM (150 KB) + 16 KB SPI-буфер.

## Тести логіки — на хості

```bash
rustc --edition 2021 --test src/game.rs -o /tmp/jewels_tests && /tmp/jewels_tests
# running 2 tests ... test result: ok
```

На платі ті самі перевірки (`game::selftest_checks()`, **2247 асертів**) йдуть при старті:

```
JEWELS: самотести логіки: OK (2247 перевірок)
JEWELS: старт; повний кадр 36 ms (SPI 40 MHz, DMA)
```

Покрито: генерація без готових ліній і з гарантованим ходом, пошук ліній (горизонталь/вертикаль,
без хибних спрацьовувань на «латинському квадраті»), «мертве» поле без ходів, прибирання + очки,
гравітація з досипанням (порядок каменів зберігається, порожніх клітинок не лишається),
swap-хід, 300 випадкових ходів із каскадами й інваріантами, `shuffle` зберігає набір каменів.

## Правила й керування

| | |
|---|---|
| тап по каменю | вибрати (біла рамка) |
| тап по сусідньому | обмін; якщо лінії 3+ немає — камені їдуть назад |
| очки | `прибрано × 30 × номер каскаду` (каскад = ланцюжок після падіння) |
| NEW | нова гра |
| тап по оверлею | якщо ходів не лишилось — поле перемішується, далі «TAP TO PLAY» |

Камені розрізняються **і формою, і кольором** (6 видів): коло, квадрат, ромб, трикутник, кільце, плюс —
щоб грати можна було навіть якщо панель передає кольори з відхиленням.

## Як зроблено

| що | як |
|---|---|
| кадр | `static mut FB: [Rgb565; 320*240]` (150 KB) у внутрішній RAM; у дисплей їде лише змінена ділянка (`present_rect`) |
| поле | 8×8, клітинка 26 px, проміжок 2 px → 226×226, панель 86 px праворуч |
| обмін | 3 проміжні кадри: два камені лінійно їдуть назустріч (`draw_swap_frame`) |
| збіг | кадр «спалаху»: клітинки змішуються з білим на 58 % (ручний блендинг у framebuffer), 70 ms |
| падіння | `Board::collapse()` повертає список рухів `from→to` (нові камені мають `from_r < 0`), UI інтерполює 3 кадри |
| каскад | цикл `find_matches → clear → flash → collapse` з множником, поки є лінії |
| «мертве» поле | `Board::has_move()` перевіряє всі сусідні пари; якщо ходів немає — `Board::shuffle()` (Fisher–Yates, без зміни набору) |
| тач | 2.5 MHz на час читання, назад на 40 MHz перед кожним `present`; калібрування — константи з NVS `touchcal` (спільні з C-прошивками) |

## Діагностика

`--features framedump` — після першого кадру віддає framebuffer у UART (`SNAPBEGIN 320 240 640`,
307 200 hex-символів, `SNAPEND`) — так перевірялась розкладка й палітра без «окоміра».

`--features demo` — автогра: кожні ~450 ms робить випадковий **дійсний** хід (`find_valid_move()`),
тобто проганяє обміни, спалахи, падіння й каскади. Прогін 60 с: рахунок до 10 680, каскади до 2,
жодного паніка; один хід ≈ 0.9 s разом з паузою (обмін 63 ms + каскад ≈ 175 ms).

## Пастки (успадковані й нові)

1. **`esp-println` має бути з `features = ["uart"]`, а не з типовим `auto`** — інакше на цій платі
   (два USB-порти) друк іде в native-USB і програма «зависає» на першому ж записі. Деталі — в
   `nm-cyd-c5-2048-rs/README.md` і `~/Projects/Esp32/AGENTS.md`.
2. **Камені за формою, не тільки кольором**: перша палітра дала два майже однакові рожеві види
   (`0xE24A4A` проти `0xC24AE2`) — довелося розвести до чистого червоного/мадженти й додати різні
   силуети.
3. `embedded-graphics` не має «ромба» — малюється двома трикутниками; кільце — коло + коло кольору
   клітинки всередині.
4. `fill` у моєму `DrawTarget` працює смугами (швидко), а `Circle`/`Triangle` йдуть через `draw_iter`
   поколіночно — на 64 каменях це все одно миттєво (десятки тисяч записів у RAM).
