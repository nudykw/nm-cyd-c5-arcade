# «Три у ряд» на Rust — NM-CYD-C5 (ESP32-C5)

Той самий ігровий сценарій, що й у `nm-cyd-c5-ttt` (C + LVGL), але **повністю переписаний на Rust**:
bare-metal `esp-hal 1.2.2`, `#![no_std]`, **без RTOS, без LVGL, без алокатора**.

```
nm-cyd-c5-ttt-rs/
├── Cargo.toml          esp-hal (esp32c5), mipidsi, embedded-graphics, embedded-hal-bus, esp-println
├── .cargo/config.toml  target riscv32imac-unknown-none-elf, runner = espflash --chip esp32c5
├── rust-toolchain.toml channel = stable (1.99.1)
└── src/bin/main.rs     вся гра (~450 рядків): шина, дисплей, тач, мінімакс, малювання
```

## Збірка / заливка

```bash
cd ~/Projects/Esp32/nm-cyd-c5-ttt-rs
cargo build --release
espflash flash --chip esp32c5 --port /dev/ttyUSB0 \
  target/riscv32imac-unknown-none-elf/release/nm-cyd-c5-ttt-rs
```

`espflash 4.7.0` знає `esp32c5` — заливає сам, разом з `esp-bootloader-esp-idf` (bootloader на `0x2000`).

## Порівняння з C/LVGL-версією

| | C + LVGL 9 (`nm-cyd-c5-ttt`) | **Rust esp-hal (цей проект)** |
|---|---|---|
| розмір app | **745 KB** | **41 KB** (у 18 разів менше) |
| стек технологій | IDF 5.5.6, LVGL, TTF-шрифти, `esp_lcd` | esp-hal, `mipidsi`, `embedded-graphics` |
| шрифт UI | Liberation/Adwaita (кирилиця через `lv_font_conv`) | вбудований `FONT_9X18_BOLD` (**лише ASCII**, тому підписи англійською) |
| калібрування тача | майстер на екрані + NVS | **константи в коді** (взяті з NVS C-версії; NVS у bare-metal не використовується) |
| малювання | фреймбуфер-смуги, антиаліасинг | прямі примітиви (лінії/кола), перемальовка всього екрана |
| гра | та сама логіка мінімакса | та сама логіка мінімакса |

## Продуктивність: виміри (усі на цій платі)

Повний кадр 320×240 = 153 600 байт. Міряно `esp_hal::time::Instant` навколо `set_pixels`:

| варіант | SPI | буфер `mipidsi` | повний кадр | хід (клітинка+статус) |
|---|---|---|---|---|
| без DMA | 20 MHz | 2 KB | **75 ms** | ~29 KB ≈ 15 ms |
| **DMA** (`with_dma`) | 20 MHz | 2 KB | **67 ms** | — |
| **DMA** | 20 MHz | 16 KB | **66 ms** | ~13 ms |
| **DMA (зараз)** | **40 MHz** | **16 KB** | **36 ms** | **~5 ms** |

Що з цього видно:

- теоретичний мінімум для 150 KB на 20 MHz — 61.4 ms; DMA дає 66 ms, тобто **93 % ефективності**,
  тож накладні майже нульові і подальший «розгін коду» нічого не дасть;
- **DMA ≠ швидший SPI**: такт той самий, виграш лише 75 → 66 ms (CPU не годує FIFO побайтово).
  Справжнє прискорення дає **частота**: 20 → 40 MHz = рівно 2× (66 → 36 ms);
- значно більший буфер `mipidsi` (2 KB → 16 KB) дає всього 1 ms: з DMA транзакційні накладні вже малі;
- **40 MHz перевірено на живому екрані — артефактів немає** (власник плати дивився на дрібний текст,
  рамки й кола). У C/LVGL-версії на 40 MHz було видно 2–3 збиті пікселі, але там текст іде
  з антиаліасингом (4 bpp), а в Rust — суцільними пікселями, тому й чистіше.
  Якщо колись з'явиться шум: `SPI_HZ_LCD` → `20_000_000` (ціна — 66 ms/кадр, все одно непомітно для гри).

## Технічні рішення та граблі

1. **Одна SPI-шина на дисплей і тач.** `RefCellDevice` з `embedded-hal-bus` дає два `SpiDevice`
   поверх одного `Spi`. Дисплею треба 20 MHz, тачу — 2.5 MHz, тому перед кожним читанням тача
   шина перемикається: `bus.borrow_mut().apply_config(&touch_cfg)`, а перед малюванням —
   назад на `lcd_cfg`. **Забути перемкнути назад не смертельно, але кадр стає в 8 разів довшим.**
2. **Орієнтація**: потрібна MADCTL `0xA0` (поворот 3) — у `mipidsi` це
   `Orientation::new().rotate(Rotation::Deg270)` (у бібліотеці `Deg90` = `0x60`, `Deg270` = `0xA0`).
   `Deg90` дає дзеркальний текст, як і `swap_xy` без `mirror_y` в C-версії.
3. **`esp-println` працює лише після `esp_hal::init()`** — самоперевірку ШІ довелось переносити після
   ініціалізації, інакше в лог не приходило нічого (UART ще не тактований).
4. **`Output::set_low()/set_high()` у esp-hal 1.2 непровалювані** (`&mut self`, без `Result`) —
   `.ok()` на них не компілюється.
5. **Трейт `SpiBus` треба імпортувати явно** (`use embedded_hal::spi::SpiBus`), інакше
   `transfer_in_place` «не існує» на `Spi`.
6. **DMA для шини** (`Spi::with_dma(p.DMA_CH0)` → `SpiDma`) — потрібна фіча `unstable` у esp-hal,
   бо `impl SpiBus for SpiDma` позначений `#[instability::unstable]`. Тач при цьому працює так само:
   `apply_config()` на 2.5 MHz перед читанням і назад на `SPI_HZ_LCD` перед малюванням.
7. **Продуктивність: малювати в RAM, відправляти пачкою.** Перша версія малювала напряму в дисплей,
   і це було дуже повільно: `embedded-graphics` для тексту й штрихованих ліній/кіл кличе `draw_iter`
   на **кожен піксель**, а кожен піксель через `mipidsi::DrawTarget` — це окрема транзакція
   `SET_COLUMN/SET_ROW` + 2 байти даних (тисячі транзакцій на кадр).
   Тепер: **статичний фреймбуфер 320×240 (150 KB) у внутрішній RAM** + власний `DrawTarget`
   (просто записи в пам'ять), а на дисплей — `Display::set_pixels()` одним пакетом
   (вікно адресації ставиться раз, далі йде суцільний потік пікселів).
8. **Часткові оновлення.** Хід гравця = одна клітинка (96×54 = 10 KB) + смуга статусу (320×30 = 19 KB),
   тобто ~29 KB замість 150 KB. Повний кадр (нова гра/зміна режиму) — 150 KB ≈ 62 ms на 20 MHz;
   часткове оновлення ходу ≈ 12–15 ms.
7. **Без алокатора**: буфери на стеку (`[u8; 2048]` для `mipidsi`), рядки — `heapless::String<24>`.

## Перевірено живьом (лог UART)

```
selftest 1 (порожня дошка -> центр 4): 4 OK
selftest 2 (X:0,1 -> блок 2): 2 OK
selftest 3 (O:3,4 -> виграш 5): 5 OK
TTT-RS: старт, екран намальовано, чекаю дотику
```

App/part. size: **40,960 / 16,384,000 bytes (0.25 %)** — заливка через `espflash`, чип визначено як
`esp32c5 (revision v1.0)`, 16 MB флеш, MAC `38:44:be:24:92:f4`.

## Що на екрані

```
X 0 : 0 O   D:0                        TURN: X
┌──────────┬──────────┬──────────┐
│    X     │    O     │          │     клітинка 96×54
├──────────┼──────────┼──────────┤
│          │    X     │          │
├──────────┼──────────┼──────────┤
│    O     │          │          │
└──────────┴──────────┴──────────┘
[ NEW ]                        AI: ON
```

- клітинка → хід; «NEW» → нова партія; «AI: ON/OFF» — перемкнути режим (два гравці / проти ШІ);
- виграшна лінія підсвічується темно-зеленим, у верхній смузі — рахунок і чий хід.

## Куди розвивати

- **кирилиця**: `embedded-graphics` має лише ASCII-шрифти; українські підписи = власний
  `MonoFont` (генератор `eg-font-*`/`bdf2eg`) або малювати текст вручну;
- **асинхронний DMA** (`SpiDma<Async>` + `embedded-hal-async`) — щоб малювати наступний кадр,
  поки попередній ще йде по шині (mipidsi 0.10 має лише блокуючий інтерфейс, тому зараз DMA
  блокуючий);
- **калібрування в flash** через `esp-storage` (тоді NVS-сумісність із C-версією не потрібна);
- **DMA для SPI** (`esp-hal` `SpiDma` + `mipidsi`), щоб кадр ішов без участі CPU.
