# «2048» на Rust — NM-CYD-C5 (ESP32-C5)

Та сама гра, що й `nm-cyd-c5-2048` (C + LVGL 9), але **повністю на Rust**: bare-metal
`esp-hal 1.2.2`, `#![no_std]`, **без RTOS, без LVGL, без алокатора**.
Дисплей — `mipidsi` + `embedded-graphics`, тач — власний мінімальний драйвер XPT2046.

```
nm-cyd-c5-2048-rs/
├── Cargo.toml            esp-hal/mipidsi/embedded-graphics; features: framedump, demo
├── .cargo/config.toml    target riscv32imac-unknown-none-elf, runner = espflash --chip esp32c5
├── .cargo/esp-config.toml  порожній (його вимагає include у config.toml)
├── rust-toolchain.toml   channel = stable (1.99.1)
├── src/lib.rs            pub mod game
├── src/game.rs           правила 2048 + самотести (компілюється і на хості!)
└── src/bin/main.rs       залізо, малювання, ввід, анімація, оверлеї
```

## Збірка / заливка

```bash
cd ~/Projects/Esp32/nm-cyd-c5-2048-rs
cargo build --release                    # ~4 с інкремент, ~1.5 хв з нуля
espflash flash --chip esp32c5 --port /dev/ttyUSB0 \
  target/riscv32imac-unknown-none-elf/release/nm-cyd-c5-2048-rs
```

Розмір: **57 KB** app (у 12 разів менше за C+LVGL-версію 722 KB), повний кадр **36 ms** (SPI 40 MHz + DMA).

## Тести логіки — на хості, без плати

`game.rs` не залежить від `esp-hal`, тому його можна зібрати звичайним `rustc`:

```bash
rustc --edition 2021 --test src/game.rs -o /tmp/game_tests && /tmp/game_tests
# running 2 tests ... test result: ok. 2 passed
```

Ті самі перевірки (`game::selftest_checks()`, **1720 асертів**: злиття, «нічого не змінилось»,
4 напрямки, перемога, поява плитки, 2000 випадкових ходів з інваріантами) проганяються на платі
при старті:

```
G2048: самотести логіки: OK (1720 перевірок)
G2048: старт; повний кадр 36 ms (SPI 40 MHz, DMA)
```

## Керування

| дія | що робить |
|---|---|
| **свайп по полю** | хід у бік свайпу (поріг 18 px) |
| **стрілки праворуч** (▲◀▼▶) | те саме кнопками (страховка для резистивного тача) |
| **NEW** | нова гра |
| тап по оверлею | після перемоги — «продовжити», після поразки — нова гра |

Рекорд живе **в RAM** (bare-metal без NVS); у C-версії він у NVS `g2048/best`.

UI англійською («SCORE / BEST / NEW»): `embedded-graphics` має лише ASCII-шрифти
(`FONT_6X10`, `FONT_9X18_BOLD`, `FONT_10X20`), кирилиці в них немає. У C-версії кирилиця є
(шрифти `lv_font_conv`).

## Як зроблено

| що | як |
|---|---|
| кадр | `static mut FB: [Rgb565; 320*240]` у внутрішній RAM (150 KB) — малюємо в RAM, потім `present_rect()` віддає ділянку однією пачкою `set_pixels` (інакше `embedded-graphics` робить транзакцію на **кожен піксель**) |
| що і коли перемальовується | анімація ходу — 3 проміжні кадри дошки (230×230) + фінальний; панель рахунку — лише коли рахунок змінився; оверлей — повний кадр |
| анімація | `draw_board_anim(st, f)`: позиція плитки лінійно інтерполюється `from → to`, `f = 1..4`; хід триває **~124 ms** (виміряно в демо-режимі) |
| тач | `Touch::read_raw()` перемикає шину на 2.5 MHz (`apply_config`), після чого дисплей повертає 40 MHz перед кожним `present`; калібрування — ті самі константи, що C-версія тримає в NVS `touchcal` |
| кути | плитки й «лунки» — `RoundedRectangle` з радіусом **8 px**. `embedded-graphics` малює дугу **скан-лініями без антиаліасингу**, тому кути східчасті, але без проміжних відтінків — на відміну від LVGL, де `radius` додавав «пилюку» |
| «сніг» | шрифти 1 bpp + не-AA кути (див. `BOARDS.md`); у кадрі **10–12 унікальних кольорів** |

## Діагностика

### `--features framedump` — знімок кадру в UART

```bash
cargo build --release --features framedump && espflash flash ...
# через ~0.5 с у /dev/ttyUSB0 піде: SNAPBEGIN 320 240 640, 307 200 hex-символів, SNAPEND
```
Корисно, коли треба подивитися, що саме малює гра, не дивлячись на панель (так перевіряли
розкладку: 320×240, плитки, панель, стрілки — усе на місці). Дані — по 64 байти в рядку, MSB-first
(так їх шле `mipidsi`).

### `--features demo` — автогра без рук

Ходи кожні ~140 ms по колу (вліво/вниз/вправо/вверх), оверлей перемоги закривається тапом
«програмно», поразка — нова гра. Прогін 40 с: рахунок дійшов до 1636, усі ходи по **124 ms**,
жодного паніка. Так перевіряються анімація, поява плиток, перемальовка панелі й оверлеї.

## ⚠️ Головна пастка: `esp-println` і два USB-порти

`esp-println` за замовчуванням має фічу **`auto`**: перед кожним записом він перевіряє, чи
**USB-Serial-JTAG** бачив SOF-пакети від хоста, і якщо так — друкує **в JTAG, а не в UART0**.

На цій платі обидва USB-порти підключені (CH340 → `/dev/ttyUSB0` і native USB → `/dev/ttyACM0`),
тому `auto` «перемикається» на JTAG, і щойно його FIFO заповнюється (кілька рядків), **запис
блокується назавжди** — програма виглядає як зависла: у UART лог обривається, ребуту немає.

Саме через це «зависали» і цей проєкт, і `nm-cyd-c5-ttt-rs` (він досі з `auto`).

**Рішення** — примусово UART:

```toml
esp-println = { version = "0.18.0", default-features = false, features = ["esp32c5", "uart", "critical-section"] }
```

Або читати `/dev/ttyACM0` (тоді FIFO не переповнюється) — але з CH340 зручніше.
Діагностика: якщо лог обривається на кількох рядках, а в `/dev/ttyACM0` тим часом іде
`alive N` — це воно.
